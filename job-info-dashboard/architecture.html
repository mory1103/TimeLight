04

状態モデル

「保存する状態」と「一時的な表示状態」を分けているのが要点です。ローディングとエラーは枠ごとに独立しているので、1枠が更新中でも他の枠は操作できます。

Persisted — 保存する

panels

各枠の記事リストと更新日時。次回もそのまま表示される。

customKeyword

自由枠のキーワード。保存ボタンで永続化。

Ephemeral — 保存しない

loading

枠ごとの「検索中」フラグ。押した枠だけ true。

error

枠ごとの失敗フラグ。1枠のエラーが他枠に波及しない。

05

更新シーケンス

更新ボタンを押してから画面が書き換わるまで。この順で処理が進みます。

1
押した枠だけローディング開始
loading[panelId] = true にして「検索中… 10〜30秒かかります」を表示。ボタンは無効化し多重リクエストを防ぐ。
2
Claude API を Web検索付きで呼ぶ
検索指示を埋め込んだプロンプトを送信。APIキーは環境側で処理されるため渡さない。
3
テキストブロックを結合してパース
content から type==="text" のブロックだけを結合 → コードフェンスを除去 → JSON.parse。
4
既読状態を引き継ぐ
前回と同じ URL の記事があれば、その既読フラグを新しい記事に引き継ぐ。
5
記事リストを置き換える
追記ではなく置き換え。更新日時（updatedAt）を記録する。
6
window.storage に保存
全状態を1キーにまとめて書き込む。
7
ローディング終了・再描画
失敗時は「取得に失敗しました。もう一度お試しください」を表示し、前回の記事は消さない。
06

永続化（window.storage）

キーは dashboard-state の1つだけ。全状態をこの1キーにまとめて保存します（パネルごとに分けない＝レート制限対策）。

// 1キーに全状態をJSON文字列で保存する
{
  "panels": {
    "wordpress": {
      "updatedAt": "2026-07-06T14:30:00.000Z",
      "items": [
        { "title": "…", "summary": "…",
          "url": "…", "source": "…", "read": false }
      ]
    },
    "hrtech":  { … },
    "design":  { … },
    "custom":  { … }
  },
  "customKeyword": "設定したキーワード"
}
起動時
storage.get で読込。初回はキーが無くエラーを投げるので try/catch で初期状態にフォールバック。
更新成功時
記事リストと更新日時を保存。
既読チェック切替時
即座に保存。再訪後も既読が保持される。
キーワード保存時
自由枠のキーワードを保存。
07

設計上の約束（Artifact環境の制約）

この4つを守ることが、Artifact 環境で確実に動く条件です。

単一ファイルの Reactdefault export・必須props なしで完結させる。
Tailwind コアのみ任意値 [...] は使わない。
ブラウザ保存API 不使用localStorage / sessionStorage は使わず window.storage だけ。
フォームタグ 不使用<form> は使わず onClick / onChange で処理。
